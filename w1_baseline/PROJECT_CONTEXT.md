## 1. 一句话方向

**Green Sight AI** 上学期已能监测并按简单阈值动作；本学期升级 **App（易用界面 + 多数据综合决策模型）** 与 **硬件（功能安全 + 外观）**，把「单阈值凭感觉」升级为「多数据 → 结论 → 执行方案」。

|---|---|

## 3. 本学期升级范围

### 线 1 — App

- 界面与交互更友好（状态、模块、正在执行的动作一眼能懂；手动接管清晰）。
- **接入模型：**  
  输入 = 多路传感器读数（及植物/模块上下文）  
  输出 = 状态结论 + 处理方案（可执行动作集）  
  执行 = 驱动现有/优化后的硬件  
- 保留旧阈值模式作 **baseline 对照**（用于真机 before/after 证据）。

### 线 2 — 硬件

- **功能：** 传感与执行更稳；补安全措施（防过浇、空泵、漏水/电气等，以风险清单为准）；动作日志完整。
- **外观：** 更接近消费级产品观感，服务演示与用户测试。
- **不改主叙事为「今年才模块化」**——模块化是已有基础。

```text
多传感器数据 ──► 模型（综合判断）──► 状态结论 + 处理方案 ──► 执行器
                      ▲
              对比：旧单阈值 if-then（凭感觉）
```

## 4. 用户 / 问题 / 价值（工作假设，待测）

**可证伪问题陈述（待 Week 2 验证）：**  
想自动养护的人（如学生、家庭种植者）即使有监测或简单自动装置，仍无法信任系统会「科学地」照顾植物：现有逻辑常是单阈值凭感觉触发，既不综合多维数据，产品本身又难用、外观与安全像原型。

**价值主张（工作版）：**  
Green Sight AI：在已有模块化监测与执行能力上，用 **更友好的 App** 与 **多数据综合决策模型** 生成并执行养护方案，同时把硬件做得更安全、更好看。

**USP 假说：**  
不是又一个「湿度低于 X 就动作」的设备，而是 **综合多传感器 → 结论 → 方案 → 执行**，并配套可用的 App 与更可展示的硬件。

**竞品/替代（至少 3 个，本学期重做）：**  
人工+提醒；便宜湿度报警/自吸水盆；其他简单阈值自动养护设备；只建议不执行的养护 App。

## 5. 模型要解决的具体缺口

| 旧逻辑（基线） | 新逻辑（本学期） |
|---|---|
| 单变量：湿度 &lt; 阈值 → 加湿 | 综合温湿度等（及可得的其他读数） |
| 阈值凭感觉拍脑袋 | 数据集 + 真机试验日志训练/校准 |
| 直接动作，缺少「结论」层 | 先状态结论，再处理方案，再执行 |
| 难解释为何这样动 | 决策可回放、可与旧阈值对比 |

**安全底线：** 最大动作量/时长；空泵/过浇等保护；手动优先；模型失效不得造成明显安全事故；自动动作全日志。
